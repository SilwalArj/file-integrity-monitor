# File Integrity Monitor

A beginner-friendly Python security tool that monitors files using **SHA-256 cryptographic hashes** and detects changes made after a baseline is created.

The project demonstrates basic defensive cybersecurity concepts, file handling, hashing, JSON data storage, and integrity monitoring.

## Features

* Create a SHA-256 baseline for files in a directory
* Detect modified files
* Detect newly added files
* Detect deleted files
* Detect unchanged files
* Store baseline hashes in a JSON file
* Read files in chunks when calculating hashes
* Handle missing files and permission errors
* Simple command-line interface

## How It Works

The program uses SHA-256 to generate a unique hash for each monitored file.

When a baseline is created, the program records:

```text id="zv1b5s"
File → SHA-256 hash
```

For example:

```json
{
    "monitored/test.txt": "886a6ca130df6e92829ee84a225bf9a552d69d57866e515180504a754b244a16"
}
```

During an integrity check, the program calculates the current hash of each file and compares it with the stored baseline.

### Detection Logic

```text id="b5by52"
Current hash == Baseline hash
        ↓
     Unchanged

Current hash != Baseline hash
        ↓
     Modified

File exists now but not in baseline
        ↓
       Added

File exists in baseline but not now
        ↓
      Deleted
```

## SHA-256 Hashing

The project uses Python's `hashlib` module:

```python
hashlib.sha256()
```

Files are read in **4096-byte chunks** rather than loading the entire file into memory at once.

This is handled by:

```python
while chunk := file.read(4096):
    sha256.update(chunk)
```

This approach is useful when working with larger files.

## Why File Integrity Monitoring Matters

File integrity monitoring can help identify unexpected changes to important files.

A change in a file produces a different cryptographic hash, allowing the program to detect that the file's contents are no longer identical to the stored baseline.

Real-world file integrity monitoring systems can be used as part of broader security monitoring processes.

This project is a simplified educational implementation.

## Limitations

This project is intentionally simple and is not intended to replace professional file integrity monitoring systems.

Current limitations include:

* Only files directly inside the selected directory are monitored
* No recursive subdirectory scanning
* Baseline is stored locally
* No authentication or access control
* No automated monitoring in the background
* No email or notification system
* No database
* Baseline files can be manually modified
* No digital signing of the baseline
